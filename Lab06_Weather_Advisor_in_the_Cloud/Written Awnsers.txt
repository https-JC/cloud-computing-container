Reflection
Secrets and management in SSM parameters-
Storing secrets like database passwords and API keys in AWS SSM parameter store as encrypted values allows for dynamic retrieval at runtime via least privilege roles. this prevents the credentials from being exposed in plaintext environment files or commits or even EC2 launch templates. 

turning off RDS backups-
turning off RDS backups with a retention set to zero elimates automated snapshot storage fees and allows for the quick teardown of a process during testing. the cost of disabling backups would be the cpmlete loss of point in time recovery. this can be an issue for destructive querys or data currouption if this was to occur there would be no automated backups to fall back on. this should not be used in a full production environment

15.1 Review Q&A
-Why must database passwords never be stored in launch template user-data?

Launch template user-data is stored unencrypted in plain text within EC2 and can be inspected by any process or user with basic describe permissions on the instance.

-What is the security advantage of using IAM least-privilege roles per application tier?

It enforces strict isolation so that a compromise of a frontend or backend service does allow an attacker read or write permissions to unrelated cloud resources.

-Why do application security groups reference other security groups instead of static CIDR blocks?

Security group referencing provides dynamic segmentation that automatically tracks changing private IP addresses of instances within authorized tiers without needing hardcoded IP ranges.

-How does restricting RDS ingress exclusively from the application security group protect the database?

It completely isolates the database network interface from the public internet and untrusted subnets, ensuring that only verified application instances running the correct security group can establish a TCP connection.

-Why is using TLS with certificate validation (sslmode=verify-full) mandatory when connecting to RDS?

It encrypts all data in transit across the network and validates the RDS Certificate Authority certificate against the server hostname.

-What protects the Node.js database queries against SQL injection vulnerabilities?

Utilizing parameterized queries ensures user inputs are treated strictly as data rather than executable SQL syntax.

-What are the operational risks of setting backup retention to zero in production?

It permanently disables automated backups and point-in-time recovery. this leaves the database completely vulnerable to data loss from outages.

Why is escaping output data using helpers like escapeHtml() critical in the advisor web UI?

It prevents Cross-Site Scripting attacks by removing malicious injection payloads

-How do rate limiting, cache TTLs, and input validation guard against cloud cost overruns and denial of service?

Caching frequent responses and validating 5-digit zip code regex patterns early rejects malformed traffic to ensure good inputs to the API

-Why must infrastructure teardown scripts be executed in a specific order?

Cloud resources have strict dependency relationships requiring orderly teardown to prevent resource locks.
